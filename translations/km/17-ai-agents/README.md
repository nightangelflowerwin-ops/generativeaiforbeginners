## บทนำ

អេហ្វអាយភីឡែនជាតំណាងអភិវឌ្ឍន៍ដែលគួរឱ្យរីករាយក្នុង Generative AI ដែលអនុញ្ញាតឱ្យម៉ូដែលភាសាធំៗ (LLMs) ផ្លាស់ប្តូរពីជំនួយការទៅជាអ្នកភ្នាក់ងារដែលអាចអនុវត្តសកម្មភាពបាន។ យុទ្ធសាស្ត្រអ្នកភ្នាក់ងារ AI អនុញ្ញាតឱ្យអ្នកអភិវឌ្ឍបង្កើតកម្មវិធីដែលផ្តល់នូវការចូលដំណើរការឧបករណ៍ និងការគ្រប់គ្រងស្ថានភាពដល់ LLMs។ យុទ្ធសាស្ត្រទាំងនេះក៏ជួយបង្កើនការមើលឃើញ ផ្តល់ឱ្យអ្នកប្រើប្រាស់ និងអ្នកអភិវឌ្ឍអាចតាមដានសកម្មភាពដែល LLMs បានគ្រោងទុកបាន បង្កើនការគ្រប់គ្រងបទពិសោធន៍។  

មេរៀននឹងគ្របដណ្តប់តំបន់ដូចតទៅ៖

- ស្វែងយល់ថាអ្នកភ្នាក់ងារ AI ជាអ្វី - អ្នកភ្នាក់ងារ AI ជាអ្វីខ្លះ?
- ស្វែងយល់ពីយុទ្ធសាស្ត្រអ្នកភ្នាក់ងារ AI ផ្សេងៗ ៥ ប្រភេទ - តើអ្វីខ្លះដែលធ្វើឱ្យពួកវាប្លែកឆ្ងាញ់?
- អនុវត្តអ្នកភ្នាក់ងារ AI ទៅកាន់ករណីប្រើប្រាស់ផ្សេងៗ - តើពេលណាដែលយើងគួរប្រើអ្នកភ្នាក់ងារ AI?

## គោលបំណងសិក្សា

បន្ទាប់ពីចប់មេរៀននេះ អ្នកនឹងអាច៖

- ពន្យល់អំពីអ្វីដែលជាអ្នកភ្នាក់ងារ AI និងរបៀបប្រើប្រាស់វា។
- មានសេចក្តីយល់អំពីភាពខុសគ្នារវាងយុទ្ធសាស្ត្រអ្នកភ្នាក់ងារ AI ដែលពេញនិយមខ្លះៗ និងរបៀបដែលពួកវាផ្សេងគ្នា។
- យល់ថាអ្នកភ្នាក់ងារ AI ធ្វើការយ៉ាងដូចម្តេចដើម្បីកសាងកម្មវិធីជាមួយពួកវា។

## អ្នកភ្នាក់ងារ AI ជាអ្វី?

អ្នកភ្នាក់ងារ AI គឺជាផ្នែកគួរអោយរំភើបខ្លាំងនៅក្នុងពិភព Generative AI។ ជាមួយនឹងការរំភើបនេះ មកនូវការភាន់ច្រឡំខ្លះៗអំពីពាក្យនិងការអនុវត្ត។ ដើម្បីឲ្យវាងាយស្រួលនិងបូរបន់មនុស្សភាគច្រើនដែលយោងទៅលើអ្នកភ្នាក់ងារ AI យើងនឹងប្រើការបញ្ជាក់នេះ៖

អ្នកភ្នាក់ងារ AI អនុញ្ញាតឱ្យម៉ូដែលភាសាធំៗ (LLMs) អនុវត្តភារកិច្ចដោយផ្តល់ការចូលដំណើរការទៅកាន់ **ស្ថានភាព** និង **ឧបករណ៍**។

![ម៉ូដែលអ្នកភ្នាក់ងារ](../../../translated_images/km/what-agent.21f2893bdfd01e6a.webp)

មកកំណត់ន័យពាក្យទាំងនេះ៖

**ម៉ូដែលភាសាធំៗ** - ទាំងនេះគឺជាម៉ូដែលដែលយើងយោងក្នុងបូកនេះដូចជា GPT-5, GPT-4o, និង Llama 3.3 ជាដើម។

**ស្ថានភាព** - សមាសភាពនេះបង្ហាញពីបរិបទដែល LLM កំពុងធ្វើការ។ LLM ប្រើបរិបទនៃសកម្មភាពមុននិងបរិបទបច្ចុប្បន្នដើម្បីណែនាំការសម្រេចចិត្តសម្រាប់សកម្មភាពបន្ទាប់។ យុទ្ធសាស្ត្រអ្នកភ្នាក់ងារ AI អនុញ្ញាតឱ្យអ្នកអភិវឌ្ឍគ្រប់គ្រងបរិបទនេះបានស្រួល។

**ឧបករណ៍** - ដើម្បីបញ្ចប់ភារកិច្ចដែលអ្នកប្រើបានស្នើសុំ ហើយដែល LLM បានគ្រោងទុក ចាំបាច់មួយនោះគឺការចូលដំណើរការឧបករណ៍។ ឧទាហរណ៍ឧបករណ៍អាចមានដូចជា មូលដ្ឋានទិន្នន័យ API កម្មវិធីខាងក្រៅ ឬទាំងម៉ូដែលភាសាធំមួយផ្សេងទៀត!

ការបញ្ជាក់ទាំងនេះ នឹងជួយឲ្យអ្នកមានមូលដ្ឋានល្អនៅថ្ងៃស្អែកនៅពេលយើងមើលពីរបៀបអនុវត្តវា។ យើងចាប់ផ្តើមស្វែងរកយុទ្ធសាស្ត្រអ្នកភ្នាក់ងារ AI ផ្សេងៗ៖

## អ្នកភ្នាក់ងារ LangChain

[អ្នកភ្នាក់ងារ LangChain](https://python.langchain.com/docs/how_to/#agents?WT.mc_id=academic-105485-koreyst) គឺជាការអនុវត្តន៍នៃការពន្យល់ដែលយើងបានផ្តល់ខាងលើ។

ដើម្បីគ្រប់គ្រង **ស្ថានភាព** វាប្រើមុខងារដែលមានស្រាប់ដែលហៅថា `AgentExecutor`។ វារួមទទួលបាន `agent` ដែលបានកំណត់ និង `tools` ដែលអាចប្រើបាន។

`Agent Executor` ក៏ស្តុកប្រវត្តិការជជែកដើម្បីផ្តល់បរិបទនៃការជជែកផងដែរ។

![អ្នកភ្នាក់ងារ Langchain](../../../translated_images/km/langchain-agents.edcc55b5d5c43716.webp)

LangChain ផ្តល់ជូននូវ [បញ្ជីឧបករណ៍](https://integrations.langchain.com/tools?WT.mc_id=academic-105485-koreyst) ដែលអាចនាំចូលទៅក្នុងកម្មវិធីរបស់អ្នក ដែល LLM អាចចូលដំណើរការ។ ឧបករណ៍ទាំងនេះផលិតដោយសហគមន៍ និងក្រុម LangChain។

អ្នកអាចកំណត់ឧបករណ៍ទាំងនេះហើយផ្ញើវាទៅ `Agent Executor`។

ការមើលឃើញគឺជាផ្នែកសំខាន់ផ្សេងទៀតពេលពិភាក្សាអំពីអ្នកភ្នាក់ងារ AI។ វាសំខាន់សម្រាប់អ្នកអភិវឌ្ឍកម្មវិធីក្នុងការយល់ថាឧបករណ៍ណាដែល LLM កំពុងប្រើប្រាស់ និងហេតុអ្វី។ ដូច្នេះ ក្រុម LangChain បានអភិវឌ្ឍ LangSmith។

## AutoGen

យុទ្ធសាស្ត្រអ្នកភ្នាក់ងារ AI បន្ទាប់ដែលយើងនឹងពិភាក្សាគឺ [AutoGen](https://microsoft.github.io/autogen/?WT.mc_id=academic-105485-koreyst)។ ការផ្តោតសំខាន់នៃ AutoGen គឺការជជែក។ អ្នកភ្នាក់ងារ ទាំងពីរកំពុង **អាចជជែកបាន** និង **អាចប្ដូរតាមបំណង**។

**អាចជជែកបាន -** LLM អាចចាប់ផ្តើម និងបន្តជជែកជាមួយ LLM មួយផ្សេងទៀត ដើម្បីបញ្ចប់ភារកិច្ច។ វាត្រូវអនុវត្តដោយបង្កើត `AssistantAgents` ហើយផ្តល់សារពិសេសសម្រាប់ប្រព័ន្ធមួយ។

```python

autogen.AssistantAgent( name="Coder", llm_config=llm_config, ) pm = autogen.AssistantAgent( name="Product_manager", system_message="Creative in software product ideas.", llm_config=llm_config, )

```

**អាចប្ដូរតាមបំណង** - អ្នកភ្នាក់ងារអាចកំណត់មិនមានត្រឹមតែជា LLM ទេ តែអាចជាអ្នកប្រើ ឬឧបករណ៍ផ្សេងទៀតបាន។ ជាអ្នកអភិវឌ្ឍ អ្នកអាចកំណត់ `UserProxyAgent` ដែលមានភារកិច្ចផ្សព្វផ្សាយជាមួយអ្នកប្រើសម្រាប់យោបល់ក្នុងការបញ្ចប់ភារកិច្ច។ មតិយោបល់នេះអាចបន្តការអនុវត្តភារកិច្ច ឬបញ្ឈប់វា។

```python
user_proxy = UserProxyAgent(name="user_proxy")
```

### ស្ថានភាព និងឧបករណ៍

ដើម្បីផ្លាស់ប្តូរ និងគ្រប់គ្រងស្ថានភាព អ្នកភ្នាក់ងារ​ជំនួយផលិតកូដ Python ដើម្បីបញ្ចប់ភារកិច្ច។

នេះគឺជាឧទាហរណ៍នៃដំណើរការ៖

![AutoGen](../../../translated_images/km/autogen.dee9a25a45fde584.webp)

#### LLM កំណត់ជាមួយសារប្រព័ន្ធ

```python
system_message="For weather related tasks, only use the functions you have been provided with. Reply TERMINATE when the task is done."
```

សារប្រព័ន្ធនេះដឹកនាំ LLM ដែលជារួមនេះទៅមុខងារពាក់ព័ន្ធសម្រាប់ភារកិច្ចរបស់វា។ ចងចាំថា នៅក្នុង AutoGen អ្នកអាចមាន AssistantAgents ជាច្រើនដែលបានកំណត់ជាមួយសារប្រព័ន្ធខុសគ្នា។

#### ការជជែកចាប់ផ្តើមដោយអ្នកប្រើ

```python
user_proxy.initiate_chat( chatbot, message="I am planning a trip to NYC next week, can you help me pick out what to wear? ", )

```

សារនេះមកពី user_proxy (មនុស្ស) ជារឿងដែលនឹងចាប់ផ្តើមដំណើរការអ្នកភ្នាក់ងារជឿនលឿនដើម្បីស្វែងរកមុខងារដែលគួរអនុវត្ត។

#### មុខងារត្រូវបានអនុវត្ត

```bash
chatbot (to user_proxy):

***** Suggested tool Call: get_weather ***** Arguments: {"location":"New York City, NY","time_periond:"7","temperature_unit":"Celsius"} ******************************************************** --------------------------------------------------------------------------------

>>>>>>>> EXECUTING FUNCTION get_weather... user_proxy (to chatbot): ***** Response from calling function "get_weather" ***** 112.22727272727272 EUR ****************************************************************

```

ក្រោយពេលដំណើរការជជែកដំបូង សកម្មភាពអ្នកភ្នាក់ងារនឹងផ្ញើឧបករណ៍ដែលបានផ្តល់អញ្ជើញ។ ក្នុងករណីនេះ វាជាមុខងារដែលហៅថា `get_weather`។ ពាក់ព័ន្ធនឹងការកំណត់រចនាសម្ព័ន្ធរបស់អ្នក មុខងារនេះអាចត្រូវបានអនុវត្តដោយស្វ័យប្រវត្តិ ឬអាចត្រូវអនុវត្តដោយផ្អែកលើការបញ្ចូលពីអ្នកប្រើ។

អ្នកអាចស្វែងរកបញ្ជី [គំរូកូដ AutoGen](https://microsoft.github.io/autogen/docs/Examples/?WT.mc_id=academic-105485-koreyst) ដើម្បីស្វែងយល់បន្ថែមពីរបៀបចាប់ផ្តើមសាងសង់។

### ស្ថានភាព និងឧបករណ៍

**ស្ថានភាព** - ស៊ុមគ្រប់គ្រងបរិបទការសន្ទនាសម្រាប់អ្នកតាមរយៈ **threads**។ អ្នកភ្នាក់ងារតាមដានប្រវត្តិសារ (ការស្នើសុំអ្នកប្រើ ការហៅឧបករណ៍ និងលទ្ធផលរបស់វា) ដូច្នេះរាល់ជុំរាល់ជុំ កំពុងសាងសង់លើជុំមុន។ Threads អាចត្រូវរក្សាទុកដែលអនុញ្ញាតឱ្យការសន្ទនាត្រូវបានផ្អាក និងបន្តនៅពេលក្រោយ។

**ឧបករណ៍** - អ្នកផ្តល់ឧបករណ៍ដោយផ្ញើមុខងារ Python ធម្មតា។ ប៉ារ៉ាម៉ែត្រប្រភេទ Type-annotated ត្រូវបានបម្លែងឲ្យជាស្កឹមដោយស្វ័យប្រវត្តិ ដូច្នេះម៉ូដែលដឹងថា ត្រូវហៅពេលណា និងរបៀបណា (ហៅមុខងារ)។ ស៊ុមក៏គាំទ្របណ្តាញ MCP (Model Context Protocol) និងឧបករណ៍ដែលផ្ដល់សេវា ផងដែរ ដូចជា interpreter code។

នេះគឺជាឧទាហរណ៍នៃអ្នកភ្នាក់ងារតែម្នាក់ជាមួយឧបករណ៍ផ្ទាល់ខ្លួន៖

```python
import asyncio
from typing import Annotated

from pydantic import Field
from agent_framework import Agent
from agent_framework.openai import OpenAIChatClient


def get_weather(
    location: Annotated[str, Field(description="The location to get the weather for.")],
) -> str:
    """Get the weather for a given location."""
    return f"The weather in {location} is sunny with a high of 22°C."


async def main():
    agent = Agent(
        client=OpenAIChatClient(),
        instructions="You are a helpful assistant that can answer weather questions.",
        tools=[get_weather],
    )

    response = await agent.run("What's the weather in Amsterdam?")
    print(response)


asyncio.run(main())
```

ដើម្បីភ្ជាប់ទៅ Azure OpenAI នៅ Microsoft Foundry ជំនួស យក endpoint និង សញ្ញាប័ណ្ណរបស់អ្នកផ្ញើទៅ client៖

```python
from azure.identity.aio import AzureCliCredential
from agent_framework.openai import OpenAIChatClient

client = OpenAIChatClient(
    model="my-gpt-5-mini-deployment",
    azure_endpoint="https://my-resource.openai.azure.com",
    credential=AzureCliCredential(),
)
```

### workflow អ្នកភ្នាក់ងារច្រើន

កន្លែងដែលស៊ុមរំខាន់នៅពេលប្រតិបត្តិការអ្នកភ្នាក់ងារច្រើនម្នាក់រួមគ្នា។ ឧទាហរណ៍ អ្នកអាចដំណើរការអ្នកភ្នាក់ងារតែម្នាក់បន្ទាប់ពីម្នាក់ (រាល់ការផ្ទេបរិបទទៅអ្នកនឹងទៀត) ឬបែងចែកទៅប៉្រុមអ្នកភ្នាក់ងារជាច្រើនជាដំណើរការ និងសម្រួលលទ្ធផលរបស់ពួកវា៖

```python
from agent_framework.orchestrations import SequentialBuilder, ConcurrentBuilder

# ធ្វើការប្រតិបត្តិធ្វើយ៉ាងតម្រង់តម្រៀប ដោយបណ្ដាលឱ្យបរិបទការសន្ទនាទៅតាមខ្សែខ្សែ
sequential = SequentialBuilder(participants=[researcher, writer, editor]).build()

# ពង្រីកចេញទៅភាគីភ្នាក់ងារជាប្រព័ន្ធស្របពេលហើយបន្ទាប់មកបញ្ចូលចម្លើយរបស់ពួកគេជា​ទូទៅ
concurrent = ConcurrentBuilder(participants=[analyst_a, analyst_b, analyst_c]).build()
```

### ស្ថានភាព និងឧបករណ៍

ដើម្បីគ្រប់គ្រងស្ថានភាពនៃការសន្ទនា TaskWeaver ប្រើប្រាស់គំនិត `Planner`។ `Planner` គឺជា LLM ដែលទទួលសំណើពីអ្នកប្រើ ហើយរៀបចំផែនការ នៃភារកិច្ចដែលត្រូវបញ្ចប់ ដើម្បីបំពេញសំណើនេះ។

ដើម្បីបញ្ចប់ភារកិច្ច `Planner` ត្រូវផ្សព្វផ្សាយទៅកាន់សំណុំពហុឧបករណ៍ហៅថា `Plugins`។ វាអាចធ្វើជាគ្លាស Python ឬជាកម្មវិធីអញ្ជើញកូដទូទៅ។ Plugin ទាំងនេះត្រូវបានរក្សាទុកជាភស្តុតាង (embeddings) ដើម្បីឲ្យ LLM អាចស្វែងរក plugin ត្រឹមត្រូវបានល្អប្រសើរជាងមុន។

## JARVIS

យុទ្ធសាស្ត្រអ្នកភ្នាក់ងារចុងក្រោយដែលយើងនឹងស្វែងរកគឺ [JARVIS](https://github.com/microsoft/JARVIS?tab=readme-ov-file&WT.mc_id=academic-105485-koreyst)។ អ្វីដែលធ្វើឲ្យ JARVIS ជាឯកតាតែមួយ គឺវាប្រើ LLM ដើម្បីគ្រប់គ្រង `ស្ថានភាព` នៃការសន្ទនា ហើយ `ឧបករណ៍` គឺជាម៉ូដែល AI ផ្សេងៗ។ ម៉ូដែល AI រាល់មួយបានបំផុតភាពជាម៉ូដែលជំនាញដែលអនុវត្តភារកិច្ចបរិមាណកម្រិតខ្លះ ដូចជាការរកឃើញវត្ថុ ការប្រែសំឡេង ឬការបង្ហាញចំណងជើងរូបភាព។

LLM បន្ទាប់មករៀបចំសំណើក្នុងរបៀបដែលម៉ូដែល AI ជំនាញអាចបកប្រែបាន ដូចជា JSON។ ពេលម៉ូដែល AI ផ្ដល់ការព្យាករណ៍ផ្អែកលើភារកិច្ច ដែល LLM ទទួលបានចម្លើយតបវិញ។

ប្រសិនបើតម្រូវឲ្យមានម៉ូដែលជាច្រើនដើម្បីបញ្ចប់ភារកិច្ច វានឹងបកប្រែចម្លើយពីម៉ូដែលទាំងនោះ មុននឹងបញ្ចូលគ្នាសម្រេចចេញជាចម្លើយទៅអ្នកប្រើ។

ឧទាហរណ៍ខាងក្រោមបង្ហាញពីរបៀបដែលវានឹងដំណើរការប្រសិនបើអ្នកប្រើស្នើសុំការពណ៌នា និងរាប់វត្ថុនៅក្នុងរូបភាព៖

## ភារកិច្ច

ដើម្បីបន្តការសិក្សារបស់អ្នកអំពីអ្នកភ្នាក់ងារ AI អ្នកអាចសាងសង់ជាមួយ Microsoft Agent Framework៖

- កម្មវិធីដែលសម្រួលការប្រជុំអាជីវកម្មជាមួយនាយកដ្ឋានផ្សេងៗនៃក្រុមហ៊ុនចាប់ផ្តើមអប់រំ។
- បង្កើតសារប្រព័ន្ធដែលដឹកនាំ LLMs ដើម្បីយល់ពីបុគ្គលិកភាព និងអាទិភាពផ្សេងៗ និង អនុញ្ញាតឱ្យអ្នកប្រើប្រាស់បង្ហាញគំនិតផលិតផលថ្មី។
- LLM គួរបន្តបង្កើតសំណួរតាមបន្ទាត់ពីនាយកដ្ឋាននីមួយៗ ដើម្បីផ្សំបានល្អនិងធ្វើអោយគំនិតផលិតផលប្រសើរឡើង។
